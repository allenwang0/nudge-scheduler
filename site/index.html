Result

Reminders land only in the hours quiet mode allows#

The planner starts 15 minutes after the app opens and looks for the next allowed window: from the end of quiet hours to the next start. That window ends the same day only when quiet hours wrap midnight, like 22:00–08:00; otherwise it runs into the next day.[E8] Reminders are spread evenly across what is left of it, at least 15 minutes apart when there is room.

The legacy rules always spread reminders from the end of quiet hours to the start on the same calendar day.[E7] With quiet hours 01:00–07:00, that runs backwards from 07:00 to 01:00, so reminders land between 03:05 and 05:05 — inside the window.

Under the default window 22:00–08:00 the legacy rules mostly work: 2 of 238 deliveries fell inside it. The failure is specific to windows that do not wrap midnight, such as a night-shift 01:00–07:00.[E6]

The package also sends 2.6× as many reminders per day (1.75 vs 0.67 with quiet hours 01:00–07:00), so raw counts are not comparable; the share inside quiet hours is. The legacy rules cap drift priority lower (bonus up to 30 days instead of 40), never expire snoozes and do not dedupe contacts, which is consistent with the episodes they never nudge in the last column.

The baseline was re-implemented from a description of the old behavior, not from its code, and each row is a single seed.[E7]

Sensitivity

A daily cap of 3 keeps waits short without flooding the user#

At cap 1 the queue backs up: p90 19 days, longest 39 days. From cap 3 on, the p90 is at most a day and the longest wait stays at 6–7 days, because the engine already surfaces every overdue friend most days. Volume rises from 1.00 to 1.70 reminders per day between cap 1 and cap 3.

Mechanism

Each day: score overdue friends, keep the top few, place them in allowed hours#

Rings
Inner, close and outer friends are due every 10, 20 and 40 days; distant friends get no drift reminders.
Score
An overdue friend scores 50 plus one point per overdue day, up to 90; a birthday today scores 100.
Pick
One reminder per friend, sorted by score, kind, ring and id, then cut to the daily cap. Output does not depend on input order.
Place
DeliveryPlanner spaces the day's reminders inside the next allowed window, never sooner than 15 minutes after now.[E8]
Snooze
A snoozed friend is skipped for 7 days, then returns.
Inputs
now and calendar are arguments; the package never reads the system clock or time zone.

Limitations

Results cover one synthetic friend group in one time zone#

  • Synthetic friends and behavior. Reply and snooze rates are assumptions, so wait times compare settings; they do not forecast real use.[E9]
  • Re-implemented baseline. The legacy rules were rebuilt from a description, not the original code; a faithful copy could behave differently.
  • One seed per scenario. The legacy comparison and the night-shift window use seed 42 only; the cap sweep uses 20 seeds with the default window.
  • Different volumes. The package sends 2.6× as many reminders as the legacy rules, so compare shares, not counts.
  • One time zone. Every run uses America/Los_Angeles; other zones' clock changes are not simulated, though the planner reads the zone from its calendar argument.

Reproduce

Reproduce it in four commands#

Commands run from a clone of allenwang0/nudge-scheduler.

  1. Build and run the tests (Swift 6, Xcode 16 or later, macOS; no dependencies). Expect “Test run with 26 tests”.

    swift build && swift test

  2. Run the simulation (about 46 s here). It rewrites site/results.json and site/card.json; with seed 42 the results file is byte-identical to the committed one.

    swift run -c release nudge-sim --seed 42 --out site
git diff --exit-code site/results.json

  3. Rebuild this page and the README block from the results (Python 3.10+, standard library).

    python3 scripts/build_report.py --readme README.md

  4. Check that the page's numbers match results.json.

    python3 -m unittest discover -s scripts -p 'test_*.py'
